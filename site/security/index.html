Security

Security model

The gate enforces, the human decides. The agent can neither reach the console nor change the policy.

Non-negotiable requirements

  • Console in its own container

    Under its own account (lockhttp), the only container with the policy volume. The agent gets neither its socket nor the Docker socket.

  • NeverAuto, always

    Every hub ticket the gate makes is NeverAuto. Neither lox run’s auto mode nor an auto rule answers a held request: a human does.

  • Identical fingerprint

    One human decision covers only requests with the same container, method, URL, significant headers and normalised body.

  • LLM API relay checks

    Once TLS is decrypted, the Claude API’s mcp_servers, server tools other than web_search, files and foreign credentials never pass without a human.

  • Hub-attached only

    The gate does not start without its hub flags. When the hub is unreachable, nothing else approves: the ticket stays pending.

  • Fail closed

    No console, an unknown source, an unreadable source map, a policy that does not decode: asks are refused, errors deny.

What it protects

Assets: the project’s and the host’s data, credentials, and actions taken online in your name.

Attackers: the agent itself (prompt injection, drift) and hostile web content.

Out of scope: a compromised host or console account, any account that may run docker on the host, the model provider itself (Anthropic), a network attacker upstream.

Audit

The gate writes free and denied requests to a daily JSONL file, kept 30 days. The console writes every ask to its audit log.

Both carry the same request_id, the container, the declared agent and how it was attributed. The audit never holds a body or a secret.

The container is known for sure: one internal network per container. The agent is an attribution, not an authentication, because agents of one container share a uid.

Known limits

  • Without decryption, a CONNECT opens reads and writes. An approved host stays open for connect_grant (10 minutes by default), content unseen.
  • HTTP/1.1 only to clients when decrypting. The gate refuses Upgrade: h2c.
  • A WebSocket session is one approval. The upgrade is decided; the frames that follow are not.
  • Heuristics run in shadow by default, until you set heuristics = "enforce".
  • No MCP server. Agents meet lockhttp as a proxy; its 403 pages tell them what to ask of you.

Report a vulnerability

Please do not open a public issue. Report it privately as described in SECURITY.md (a private GitHub security advisory).
