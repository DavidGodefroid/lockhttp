Security model

The gate enforces; the human decides; the agent can neither reach the console nor change the policy.

Pre-release. lockhttp v0.4.0 is out as a pre-release and runs in Docker only (one lockhttp launcher, a cosign-signed image): command names are fixed, flags may still move. TLS decryption ships in it and is optional, wired by lea: without a local CA and the signer (--ca-cert, --signer), HTTPS is decided at the domain. Design decisions: docs/decisions.md, contract with lea: docs/lea.md.

Non-negotiable requirements

  • Console in its own container

    Under its own account (lockhttp), the only container with the policy volume. The agent gets neither its socket nor the Docker socket.

  • NeverAuto by default

    Only an approved auto rule, scoped to a container, can be answered by auto mode, and the console re-checks the rule against its own approved policy first.

  • Identical fingerprint

    One human decision covers only requests with the same container, method, URL, significant headers and normalised body.

  • Claude API allowlist

    Once TLS is decrypted, mcp_servers, server tools other than web_search, files and foreign credentials never pass without a human.

  • Fail closed

    No console, an unknown source, an unreadable source map, a policy that does not decode: ASK is refused, errors deny.

Threats and answers

Assets: the project’s and the host’s data, credentials, and actions taken online in your name. Attackers: the agent itself (prompt injection, drift) and hostile web content. Out of scope: a compromised host, Anthropic, a network attacker upstream.

Audit

The gate writes FREE and DENY to a daily JSONL file, kept 30 days; the console writes every ASK to its audit log. Both carry the same request_id, the container, the declared agent and how it was attributed. The audit never holds a body or a secret.

The container is known for sure (one internal network per container). The agent is an attribution, not an authentication: agents of one container share a uid.

Report a vulnerability

Please do not open a public issue. Report it privately as described in SECURITY.md (a private GitHub security advisory).
