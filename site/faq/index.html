FAQ

Frequently asked questions

Short answers, each drawn from the README and the docs. For anything not covered here, see the usage guide.

Is lockhttp ready to use?

It is usable, not yet stable: v0.11.0 is out, a full release built on lockkit v0.20.0. Command names are fixed; until v1.0.0 a minor release may still change a flag or the policy format, and the changelog lists every such change.

Try it and report what breaks.

Which AI agents does it work with?

Any agent and any HTTP client: lockhttp is a proxy, not an agent plugin. It sees requests, whatever tool sent them.

The agent must run in lea, which runs Claude Code in containers today.

Do I need lea?

Yes, for now. lockhttp relies on lea’s topology: each agent container on its own internal network, a proxy container as the only way out, and a source map naming the container behind each address.

The gate is a plain HTTP(S) proxy, but the guarantee comes from that topology.

Why not a simple domain allowlist?

Because an allowed domain is allowed for reads and writes. lockhttp keeps reads of trusted hosts free, and stops writes, uploads and unknown hosts for a human, with a trace of who asked.

What happens when nobody answers?

A request that needs a human is held 60 s, then refused with E_PENDING. The ticket stays pending on the hub, and the same request goes through once you approve it.

When the ticket expires unanswered, the agent gets E_TIMEOUT. With no console running, asks are refused at once with E_NO_CONSOLE, while trusted reads continue.

Does lockhttp decrypt my traffic?

Only if you turn it on. Without it, lockhttp decides HTTPS on the host name and port (CONNECT and SNI).

With a CA made per installation (lockhttp ca init), trusted only inside lea’s containers, and the signer that holds its key, the gate decrypts and decides each request. Hosts that pin their certificates go in a splice list and stay decided at the domain.

Can the agent approve its own request?

No. Approvals happen only on lockhub, outside the agent’s containers: in lox run, lox approve, lea’s deck or a paired phone.

The hub signs your decision and the gate checks it. The agent cannot reach the hub: its containers are not on the hub’s network, and the gate refuses the hub’s addresses as targets.

Can I let some requests through without asking?

Yes: a free rule, written and confirmed by you in the console’s review, scoped to a container or to all.

An auto rule asks like ask: every held request is a NeverAuto ticket, so lox run’s auto mode never answers it.

Can the agent call an API without holding its token?

Yes, since v0.8.0. A policy inject entry has the gate add the credential header for one exact host and port, from its own secrets file. How it works.

Is there an MCP server?

No. Agents meet lockhttp as a proxy; its refusal pages tell them what to ask of you.

Which licence?

Apache 2.0, like the rest of the Lock Family.
