Install lockhttp

A host console, a gate in lea’s proxy container, and an opt-in switch in lea.

Pre-release. lockhttp v0.1.0 is out as a pre-release: command names are fixed, flags may still move. TLS decryption ships in it and is optional: without a local CA and the signer (--ca-cert, --signer), HTTPS is decided at the domain. Design decisions: docs/decisions.md, contract with lea: docs/lea.md.

Status

There is no release yet: v0.1.0 will be the first pre-release, with signed archives on the releases page. Until then you can build from source with Go:

git clone https://github.com/DavidGodefroid/lockhttp.git
cd lockhttp
go build -o lockhttp ./cmd/lockhttp
./lockhttp version

Requirements

  • A Linux host where you can use sudo once, for lockhttp install.
  • lea, which runs the agents in containers on internal networks and runs the gate in its proxy container (Docker, or rootless Podman).
  • A second login session for the lockhttp account (switch user, or a text console), where the console stays open.

Commands

CommandWhereWhat it does
lockhttp installhost, sudoCreates the lockhttp account, the lockhttp-clients group, /run/lockhttp and /etc/lockhttp/system.toml with the gate’s uid as the host sees it.
lockhttp inithost, as lockhttpWrites the policy (~lockhttp/.config/lockhttp/config.toml). --trusted imports lea’s LEA_EGRESS_ALLOW as trusted read-only hosts.
lockhttp consolehost, as lockhttp, own sessionThe approval console: approvals, policy review, auto mode, audit.
lockhttp doctorhostChecks the setup.
lockhttp gatelea proxy containerThe HTTP(S) proxy. lea starts it; you do not.
lockhttp signer, lockhttp ca initlea proxy container / hostOptional TLS decryption: the local CA and the process that holds its key.
lockhttp version, helpanywhereExit codes: 0 ok · 1 refused/denied/failed · 2 no console · 3 usage/config error.

Setup with lea

  1. Separate the console. sudo lockhttp install --client <lea user> --gate-uid 10003. Under rootless Podman add --rootless: the gate’s uid is then the subuid read from /etc/subuid.
  2. Write the policy. As lockhttp: lockhttp init, optionally --trusted "<LEA_EGRESS_ALLOW>". lea never writes this file, and an agent cannot reach it.
  3. Start the console. As lockhttp, in its own login session: lockhttp console --profile default. lockkit refuses any other shape.
  4. Turn it on in lea. LEA_LOCKHTTP=1. lea starts the gate in its proxy container, puts squid on loopback behind it, routes keyproxy through it and switches off the SSH git forwarders.
  5. Check. lockhttp doctor on the host, and lea’s own doctor: from an agent, curl --noproxy '*' https://example.com must fail.

Every file, mount and flag lea uses is in the lea integration contract.
