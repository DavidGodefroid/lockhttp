Install · v0.9.x

Install lockhttp

lockhttp runs in Docker, beside lea. On your machine you need Docker, lea, lox and the lockhttp launcher, a shell script that runs every command in the signed lockhttp image.

With Homebrew

Install with Homebrew
brew trust davidgodefroid/tap
brew install davidgodefroid/tap/lox davidgodefroid/tap/lockhttp
brew install davidgodefroid/tap/lea

Homebrew asks you to trust a third-party tap once. brew install davidgodefroid/tap/lockfamily installs the whole family instead.

  1. In lea’s projects directory (LEA_PROJECTS_DIR), lox add lockhttp asks only for the lock’s name. It writes the policy, runs lockhttp doctor --fix, shows a short review and starts the console.

    cd ~/projects
lox add lockhttp

  2. In a terminal of its own, outside lea and any agent, keep lox run open. Every held request shows up there for your decision.

    lox run

  3. Turn lockhttp on in lea’s configuration, then restart lea: lea mounts the locks’ sockets when its container starts. LEA_LOCKHTTP=1 lea is not enough: the configuration wins over the environment.

    echo LEA_LOCKHTTP=1 >> ~/.config/lea/lea.conf
lea stop --all
lea

    lea-proxy and its gate are shared by every lea on the machine: lockhttp is on or off for all of them at once, and once it is on, a lea whose projects directory has no lockhttp lock does not start. lea doctor reports the gate’s state.

lea reads .lockfamily/up.json only at the root of its projects directory: run lox add there, not in a project inside it. How lox add works.

You can also answer held requests with lox approve, in lea’s deck or on a paired phone.

Without Homebrew

The Lock Family’s installer puts the same tools as Homebrew in ~/.local/bin, without sudo (how it works):

curl -fsSL https://lockfamily.dev/install.sh | sh
lockhttp version

It verifies the cosign signature of each release and of its image. The launcher runs the image by its digest. lea uses this launcher from v0.16.0.

cosign is required. Linux (Docker Engine) and macOS (Docker Desktop); on Windows, WSL 2 with Docker Desktop.

Requirements

  • Docker, and cosign for the install script.
  • lea: it runs the agents in containers on internal networks, and runs the gate beside its proxy (Docker, or rootless Podman).
  • lockhub’s lox: the gate runs hub-attached only, and you answer held requests on the hub.

Commands

CommandWhereWhat it does
lockhttp profile addas you, on the projectAdds a profile with the default policy to the project’s .lockhttp/config.toml. lox run reviews it and copies it into the console. --trusted imports trusted read-only hosts.
lockhttp init <agent>as you, on the projectWrites nothing: lockhttp has no agent files. lea routes the agent’s HTTP through the gate.
lockhttp doctoras you, on the projectChecks the setup and the project’s policy; --fix repairs its permissions.
lockhttp policy show|edit|pathas lockhttpPrints, edits or locates the console’s copy of the policy.
lockhttp consoleits own container, as lockhttpThe policy console: it serves the approved policy to the gate and asks you about every loosening.
lockhttp gateits own container, as gateThe HTTP(S) proxy, hub-attached only. lea starts it beside its proxy with the hub flags from up.json.
lockhttp signer, lockhttp ca initsidecar container / the launcherTLS decryption: the local CA, and the process that holds its key.
lockhttp version, updateanywhereThe launcher’s and the image’s versions; a newer release’s launcher and image.

What lea does with it

With LEA_LOCKHTTP=1, lea starts the gate from the same image beside its proxy container, asking the hub that lox run serves. It puts squid on loopback behind the gate and routes its key proxy through it.

lea never writes the policy. Without a trusted up.json naming a lockhttp lock, lea stops, says why, and says to run lox run.

To check: lockhttp doctor, and lea’s own doctor. From an agent, curl --noproxy '*' https://example.com must fail.
