Your agent browses. You hold the key.

Every outbound HTTP(S) request of your AI agent goes through lockhttp. Reads of trusted hosts pass; anything that sends data or reaches an unknown host waits for you.

Install with Homebrew
brew trust davidgodefroid/tap
brew install davidgodefroid/tap/lox davidgodefroid/tap/lockhttp
brew install davidgodefroid/tap/lea

Needs Docker. The gate runs inside lea, hence its formula. Then lox add lockhttp, lox run, and LEA_LOCKHTTP=1 in lea’s lea.conf. The whole family: brew install davidgodefroid/tap/lockfamily.

Why lockhttp?

An agent that can read the web can also write to it. It can post to a webhook, push code, open an issue, or call an API with your token.

A domain allowlist cannot tell those apart: an allowed host is allowed for reads and writes. lockhttp decides per request, and keeps the decision out of the agent.

In-agent approval is a convenience; a separate approval process is a boundary.

Three verdicts

  • 🟢

    Free

    A GET, HEAD or OPTIONS without a body to a trusted host, or a request a free rule matches. It passes, and the gate logs it.

  • ✋

    Ask

    An unknown host, a write, an upload, a message. The gate holds the request (60 s) as a signed ticket on the hub. You answer y or n <reason>.

  • ⛔

    Deny

    The network floor, a secret leaving its host, a deny rule. The agent gets a 403 with a stable E_* code and what to ask of you.

LLM APIs are a relay too

A model API is not only the model’s channel. On the Claude API, mcp_servers makes the provider call a remote MCP server, and some server tools fetch or run things outside your machine.

With TLS decryption, lockhttp checks the Claude API per request. Plain messages pass; mcp_servers, server tools other than web_search and the Files API wait for a human. The rules

Highlights

  • 👤

    Never answered automatically

    Every held request is a NeverAuto ticket: lox run’s auto mode never answers it, a human does. Only a free rule you confirmed lets a request pass unasked.

  • 🔑

    Credentials injected

    The gate can add an Authorization header for one host and port, from its own secrets file. The agent calls the API without ever holding the token.

  • 🧱

    Fail closed

    No console: an ask is refused at once (E_NO_CONSOLE). An unknown source, a policy that does not decode, an error while deciding: deny.

  • 🧩

    Identical, not similar

    A decision is shared only by requests of identical fingerprint: container, method, URL, significant headers and normalised body.

  • 🕶️

    Masked previews

    The approval screen shows a masked preview of the body (PII detectors, terminal sanitising, first 1 KiB), never the clear body.

  • 🔐

    CA key out of the data plane

    For TLS decryption, a separate lockhttp signer holds the CA key and issues leaf certificates. The gate never sees the key.

  • 🌗

    Shadow mode

    mode = "shadow" logs what would have asked or been denied and lets it pass, so you can tune the policy first. The floor and secret checks stay on.

  • 🏷️

    Refusals the agent can act on

    Every refusal carries a stable code (X-LockHTTP-Code), a request id and a retry rule: retry, ask the user, or stop.

  • 📜

    Full audit

    Free and denied requests go to the gate’s daily JSONL log, asks to the console’s audit, joined by request_id. Never a body or a secret.

Quick start

lockhttp is a proxy, so it works with any agent and any HTTP client. It needs lea, which runs agents (Claude Code) in containers whose only way out is its proxy.

  1. Install with Homebrew (the box above). Docker must be running.

  2. In lea’s projects directory, lox add lockhttp asks for the lock’s name, writes the policy and starts its console.

    cd ~/projects
lox add lockhttp

  3. In a terminal of its own, outside any agent, keep lox run open. Every held request shows up there for your decision.

    lox run

  4. Turn lockhttp on in lea’s configuration, then restart lea. LEA_LOCKHTTP=1 lea is not enough: the configuration wins over the environment.

    echo LEA_LOCKHTTP=1 >> ~/.config/lea/lea.conf
lea stop --all
lea

    lea-proxy and its gate are shared by every lea on the machine: lockhttp is on or off for all of them at once.

Ask your agent to read the docs of a trusted site: it goes through. Ask it to post somewhere: the request waits for your y.

Know the limits

Without TLS decryption, lockhttp decides HTTPS on the host name. Opening a host opens its reads and its writes, and the approval screen says so.

Per-request decisions on HTTPS need a local CA, trusted only inside lea’s containers. Hosts that pin their certificates stay decided at the domain.

A slow, low-bandwidth channel to a trusted host is not something a proxy can close.
